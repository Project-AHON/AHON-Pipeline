# Source-to-target contracts

This matrix describes the executable bundle on baseline `e1e8b883a1780b3150e6c7cd880530f4d7e42e66`. A dataset can be implemented but blocked in a particular workspace by missing credentials or reviewed reference inputs. Source profile counts are expectations from the reviewed repository work, not fresh source-run evidence.

All table names below are relative to the selected catalog. Landing is `/Volumes/<catalog>/reference/<source_volume>/<dataset>/<job.run_id>/`. `_SUCCESS.json` records filenames, SHA256 digests and parsed row counts; Bronze reads only completed, verified batches. Extraction never changes a completed batch. A changed source uses a new batch ID. Delta writes are separate table transactions; a job is not a cross-table transaction.

## Identity, corrections and reconciliation

- Generic `_row_hash`: SHA256 of ordered JSON source fields with explicit nulls. Source timestamps and run IDs are excluded. `_source_digest` identifies the immutable file. `_observation_id` identifies a file digest plus raw row hash. Identical raw rows are dispositioned as repeats; manifest row counts remain the fidelity authority.
- Earthquakes use a file digest plus source row ordinal instead, retaining identical observations within a file. A changed monthly file retains earlier observations. No deduplication into earthquake events occurs.
- Retries preserve first-ingestion lineage. A new source version adds Bronze observations. Silver business-key merges update corrections without deleting absent rows. Population and CMCI reject keys include observation identity, so repeat runs do not grow duplicate quarantine records.
- Population reconciles each landed scope as accepted + rejected. Earthquake observation counts reconcile against manifests and accepted/flagged counts. CMCI response validation requires every requested locality, year and indicator before publication; later typing separates accepted values from rejects. PSGC uses deterministic deduplication within source periods. Fiscal SQL checks latest-source business keys and rejects join fan-out before materialization.
- Invalid structural files remain in extraction evidence and fail before publication. Full-snapshot deletion is not authorized. A rejected correction retains a prior accepted Silver row; downstream consumers must consult rejection and ingestion evidence before treating that row as current.

## Geography and time

`Q2_2024` is the inherited dimension snapshot, not a new claim that it is the correct reference for every historical analysis. Dimension snapshot changes require review and an isolated rebuild. Codes remain strings. Provinces, cities, municipalities, barangays, regions and submunicipalities are distinct levels. Never sum province budgets/population with their constituent localities.

BLGF matches use province context, type and reviewed overrides. Name-only and independent-city candidates without province evidence require review. Historical province splits remain unmatched unless an override is justified. Population HUC/independent-city and aggregate paths are retained; unsupported contextual mappings stay NULL. CMCI source locality → PSGC mappings require a one-to-one reviewed CSV tied to the same snapshot, including reviewer and evidence. Earthquake locality candidates never establish epicentral assignment or exposure.

The evidence output uses an explicit reporting year. Fiscal and CMCI indicators must match that year exactly. No census interpolation, future-value backfill, temporal nearest-neighbor join, weighting, or gap-score subtraction is implicit.
