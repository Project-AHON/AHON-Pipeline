# Earthquake observations

bronze.philvolcs_earthquake_observation preserves eight CSV source STRING columns: Date-Time, Latitude, Longitude, Depth, Magnitude, Location, Month, Year, plus _source_row BIGINT and generic lineage. Identity is file digest+ordinal; identical rows are retained. Name philvolcs is preserved for repository compatibility; source is PHIVOLCS.

silver.philvolcs_earthquake_observation_clean is one row per observation. Source Date-Time/Location/Month/Year remain; typed event_time TIMESTAMP_NTZ and latitude/longitude/depth_km/magnitude DOUBLE (see exact aliases in observation_pipeline.py), raw numeric fields _raw_latitude/_raw_longitude/_raw_depth_km/_raw_magnitude STRING; parsed time/physical range violations set has_dq_issues BOOLEAN; invalid observations remain in the reject table. psgc_code STRING stays NULL. candidate_codes ARRAY<STRING> are textual candidates only, with geographic_assignment_status explicitly withheld. Source/processing lineage retained. silver.philvolcs_earthquake_reject copies invalid observations keyed observation ID; replay does not duplicate them.

No earthquake-event deduplication or event-to-LGU exposure assignment occurs. Source wallclock timezone and event correction policy require evidence. Legacy bronze.philvolcs_earthquake and silver.philvolcs_earthquake_clean are compatibility diagnostics only, not active bundle outputs.

Magnitude must be finite but has no invented nonnegative threshold: small earthquakes can have negative magnitude ([USGS explanation](https://www.usgs.gov/faqs/how-can-earthquake-have-a-negative-magnitude)). Negative reported depth is retained with a review flag because the source depth-reference convention is not established; it is not declared a physically impossible earthquake. Coordinate limits and nonfinite/missing parse checks remain explicit. Legacy diagnostics retain their older stricter contract and are not active outputs.
