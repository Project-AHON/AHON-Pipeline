# Open Street Map - Critical Infrastructures

- **Source:** OpenStreetMap critical-infrastructure shapefiles landed in the Hugging Face source volume under `/Volumes/ahon/reference/source/huggingface/critical_infrastructures`. The extraction pipeline reads `.shp` files such as `fire_station.shp`, `hospitals.shp`, `police_station.shp`, and `schools.shp` and writes the features to the bronze table.
- **Coverage:** the dataset is a point-in-time catalogue of critical infrastructure features represented in the source shapefiles. There is no explicit time dimension; freshness depends on the files uploaded to the source volume. Geography is defined by the locations carried in the shapefiles and the centroid coordinates in WGS84.
- **Owner:** to be confirmed with the data steward responsible for the governance and maintenance of the OSM critical-infrastructure source feed.

## Bronze: `ahon.bronze.critical_infrastructures`

- **One row is:** one infrastructure feature extracted from an OSM shapefile: a fire station, hospital, police station, or school record, including its original geometry metadata and computed centroid coordinates.
- **Loaded by:** `src/sql/datasets/osm_critical_infrastructures/extract/critical_infrastructures_ingest.py` and `src/sql/datasets/osm_critical_infrastructures/bronze/critical_infrastructures.sql`.
- **Row hash covers:** the raw source fields in the bronze table below, in the order `amenity`, `name`, `source_file`, `geometry_wkt`, `geometry_geojson`, `centroid_lat`, `centroid_lng`, and `loaded_at`, joined with `|` before hashing with `SHA2(..., 256)`.

| Column | Type | Description | Notes |
| --- | --- | --- | --- |
| `id` | bigint | Surrogate key for the bronze row | Derived by `xxhash64(...)` from the raw identity columns; used as the merge key for idempotent loads |
| `amenity` | string | Type of infrastructure feature | Example values are expected to be amenity categories such as `fire_station`, `hospital`, `police`, or `school` |
| `name` | string | Name of the facility | May be blank for some features; bronze keeps it as received |
| `source_file` | string | Source shapefile name | Basename of the `.shp` file, for example `hospitals.shp` |
| `geometry_wkt` | string | Geometry serialized as WKT | Used for reproducible geometry storage and downstream geometry-type extraction |
| `geometry_geojson` | string | Geometry serialized as GeoJSON | Retained for interoperability with geospatial tooling |
| `centroid_lat` | double | Latitude of the feature centroid in WGS84 | Valid range is `[-90, 90]` |
| `centroid_lng` | double | Longitude of the feature centroid in WGS84 | Valid range is `[-180, 180]` |
| `_source_loaded_at` | timestamp | Source file ingestion timestamp from the upstream extracted table | Comes from the original `loaded_at` column |
| `_source_name` | string | The dataset the row came from | Always `openstreetmap_infrastructure` |
| `_source_ref` | string | The raw source asset path in the volume | Constructed as `/Volumes//criticalinfra/openstreetmap/<source_file>` in the bronze SQL |
| `_ingested_at` | timestamp (UTC) | When the row was loaded into bronze | Set using `current_timestamp()` by the MERGE statement |
| `_batch_id` | string | The load run that wrote the row | Randomised per run and used to group a batch of rows |
| `_row_hash` | string | SHA-256 of the raw source columns as received | Covers the raw data columns above, not the provenance columns |
| `_dq_valid_lat` | boolean | Whether the latitude is present and within range | `true` when `centroid_lat` is not null and between `-90` and `90` |
| `_dq_valid_lng` | boolean | Whether the longitude is present and within range | `true` when `centroid_lng` is not null and between `-180` and `180` |
| `_dq_valid_amenity` | boolean | Whether the amenity field is populated and non-empty | `true` when `amenity` is not null and trimmed value is not empty |
| `_dq_valid_name` | boolean | Whether the name field is populated and non-empty | `true` when `name` is not null and trimmed value is not empty |

## Silver: `ahon.silver.critical_infrastructures`

- **One row is:** one cleaned infrastructure feature that has passed the bronze DQ checks and been normalized for downstream analytics.
- **Key:** `id`
- **Built from bronze by:** `src/sql/datasets/osm_critical_infrastructures/silver/critical_infrastructures_clean.sql`.

| Column | Type | Description | Notes |
| --- | --- | --- | --- |
| `id` | bigint | Surrogate key for the silver row | Generated by `xxhash64(amenity, name, source_file, centroid_lat, centroid_lng)` |
| `amenity` | string | Standardized amenity category | Lowercased and trimmed before load; removes leading/trailing whitespace |
| `name` | string | Facility name | Converted to `NULL` if blank after trimming |
| `source_file` | string | Source shapefile name | Lowercased and trimmed; kept as a file-level provenance indicator |
| `geometry_type` | string | Geometry class inferred from WKT | Derived with `REGEXP_EXTRACT(geometry_wkt, '^([A-Z]+)', 1)` |
| `centroid_lat` | double | Clean centroid latitude | Cast to double and retained only when valid |
| `centroid_lng` | double | Clean centroid longitude | Cast to double and retained only when valid |
| `geometry_wkt` | string | Geometry serialized as WKT from bronze | Retained to preserve original spatial representation |
| `geometry_geojson` | string | Geometry serialized as GeoJSON from bronze | Retained for downstream spatial consumers |
| `_source_name` | string | Provenance source name | Passed through from bronze |
| `_source_ref` | string | Source asset path | Passed through from bronze |
| `_ingested_at` | timestamp (UTC) | When the silver row was written | Carried forward from bronze provenance |
| `_batch_id` | string | The bronze batch that produced the row | Carried forward from bronze provenance |
| `_row_hash` | string | Row fingerprint for the bronze source record | Carried forward from bronze provenance |

## Data profiling

### Source profile

- The extraction script walks the UC volume recursively to discover any `.shp` files under the configured volume root.
- The expected shapefile categories in the project are critical infrastructure facilities for emergency and public services, including fire stations, hospitals, police stations, and schools.
- Geometry enrichment is performed before saving to Delta: each feature is reprojected to WGS84 if needed, and WKT, GeoJSON, and centroid coordinates are generated.

### DQ checks performed in bronze

The bronze table computes the following validation flags before writing the row:

- `centroid_lat`: valid when `NOT NULL` and between `-90` and `90`
- `centroid_lng`: valid when `NOT NULL` and between `-180` and `180`
- `amenity`: valid when `NOT NULL` and trimmed value is not empty
- `name`: valid when `NOT NULL` and trimmed value is not empty

The bronze load also filters out rows where all of the key business fields are null:

```sql
WHERE COALESCE(amenity, name, centroid_lat, centroid_lng) IS NOT NULL
```

### DQ checks performed in silver

The silver table keeps only rows that pass the main operational checks:

```sql
WHERE bronze._dq_valid_lat
  AND bronze._dq_valid_lng
  AND bronze._dq_valid_amenity
```

It additionally rejects rows when any of these fail:

- latitude outside `[-90, 90]`
- longitude outside `[-180, 180]`
- amenity is null or empty
- source file is null or empty

### Normalization performed in silver

- `amenity` is lowercased and trimmed.
- `name` is normalized with `NULLIF(TRIM(...), '')`.
- `source_file` is lowercased and trimmed.
- `geometry_type` is extracted from the leading WKT geometry prefix using `REGEXP_EXTRACT`.

## Known issues

- **The geometry is stored as text, not as a native geospatial type.** The pipeline keeps `geometry_wkt` and `geometry_geojson` strings while dropping the Shapely geometry object before Spark serialization.
- **No explicit time-based history is captured.** The source feed is treated as a snapshot of current infrastructure coverage rather than a historical time series.
- **Amenity names are variable across source shapefiles.** The bronze table keeps the raw value, while silver normalizes it to lowercase to improve consistency.
- **Some features may not carry a facility name.** The bronze and silver layers both allow `name` to be null after cleaning.
- **One row may not represent a unique facility across source files.** The surrogate key is generated from amenity, name, source file, latitude, and longitude, so a duplicate point appearing in the same or another file is treated as the same key unless the values differ.
