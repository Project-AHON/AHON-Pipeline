# CMCI executable contracts

The canonical entry point is `src/sql/datasets/cmci/pipeline.py`. Historical wide Silver tables and `cmci_pillar_score` are no longer the supported executable path. Existing incompatible schemas require reviewed migration or a fresh catalog. The source labels/codes are the 35 indicators already selected in `resources/cmci_indicators.csv`, not the complete official CMCI indicator universe.

`bronze.cmci_raw_indicator_batch_html` has one immutable source-response observation: HTML, reviewed mappings JSON, requested years JSON, PSGC source period, response-byte digest and standard lineage plus `_source_digest`/`_observation_id`. The landed JSON retains source bytes in base64. Raw row hash covers HTML, mappings, years, source period and response SHA-256; observation identity includes the delivery batch ID and landed file digest, so an identical response in a new release can recover a later invalid correction.

`reference.cmci_lgu_map` has reviewed `psgc_code`, exact `cmci_name`, `source_period`, `reviewer` and `evidence`; unique code and source-name relationships are checked. Every code must exist at city/municipality level in the selected dimension snapshot.

`silver.cmci_indicator_clean` has key `(psgc_code, year, indicator_code)`: source name, `raw_value` STRING, `raw_score` DOUBLE (nullable), `source_period`, `_source_ref`, `_row_hash`, `_observation_id`, `_ingested_at`, `_batch_id`, `_processed_at` and `has_dq_issues`. Missing `-` or blank remains NULL; nonnumeric, negative or nonfinite values are retained in `silver.cmci_reject` keyed by raw observation + logical key. Correction order is first-ingested observation time, then stable observation identity. An invalid latest correction masks a prior value in Gold until a later accepted observation recovers it.

`gold.fact_cmci_indicator` uses the same logical key and source lineage, with nullable values; it never converts absence to zero. `gold.dim_cmci_indicator` has one indicator code with label, pillar and an explicit reviewed `metric_version` metadata. The portal's numeric field is retained as `raw_score`; source units, polarity and official scoring methodology remain unspecified. A lower raw value across different indicators does not mean weaker preparedness.

`platinum.cmci_pillar_coverage` is unique by `(psgc_code, year, pillar_name)` and carries `source_period`, `expected_indicator_count`, `available_indicator_count`, `source_ingested_at`, `coverage_status` and `metric_version`. It counts nonmissing values in the selected subset. It publishes no pillar sum, official score or preparedness metric. `COMPLETE` means selected-subset completeness only.
